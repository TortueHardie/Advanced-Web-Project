# Service de Logs (Microservice)

Ce microservice est responsable de l'enregistrement et de la récupération des logs pour toutes les requêtes HTTP qui passent par la passerelle API (NGINX).

## Architecture

Le service de logs s'intègre dans l'architecture existante comme suit:

1. Chaque requête HTTP passe par NGINX (API Gateway)
2. Un middleware dans l'API Gateway NestJS intercepte la requête
3. Après traitement de la requête, le middleware envoie les données de log à l'endpoint interne `/log-write` de NGINX
4. NGINX transmet cette requête au microservice de logs
5. Le microservice enregistre les données dans MongoDB

## Schéma de données

Les logs suivent le schéma suivant:

```typescript
{
  timestamp: Date,
  method: string,
  path: string,
  status: number,
  ip: string,
  userId?: string,
  service?: string,
  responseTime?: number
}
```

## Endpoints API

Le service expose les endpoints suivants:

- `POST /api/v1/logs`: Crée un nouveau log (utilisé par le middleware interne)
- `GET /api/v1/logs?from=...&to=...&service=...`: Récupère les logs pour une période donnée, filtrable par service
- `GET /api/v1/logs/export?from=...&to=...`: Endpoint protégé pour l'exportation des logs

## Configuration

Le service se connecte à MongoDB et expose son API sur le port 3002 par défaut.

## Déploiement

Le service est déployé en tant que conteneur Docker dans l'infrastructure de microservices existante.
